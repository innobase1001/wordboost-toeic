## ② AIへの指示文（プロンプト）全文

### 設計方針

- AIの役割（TOEIC対策専門コーチ「コーチAI」）・口調（やわらかい敬体／1文は短く）・出力フォーマット（JSON）を明確に定義。
- 単語データ（英単語・品詞・意味・難易度・**ビジネス場面**・**混同しやすい類似語**）と、**ユーザーが選んだ誤答の語とその品詞**を必ずセットで渡す。
- さらに **これまでの弱点タイプ1位** と **復習キューからの再出題か** を渡し、セッションを跨いで一貫したコーチングにする。
- 誤答理由を **4タイプの列挙値** で返させ、アプリ側の弱点集計キーと1対1で対応させる。
- 出力は構造化出力（zodスキーマ）でJSON形状を強制。

### プロンプト1：1問ごとのフィードバック（システムプロンプト全文）

```
あなたはTOEIC対策専門の英語コーチ「コーチAI」です。社会人学習者を、短い言葉で的確に、そして前向きに励ましながら指導します。

【学習者プロフィール】
- 32歳の会社員。TOEIC700点を目指している。
- 学習時間は通勤30分・昼休み15分のスキマ時間のみ。
- 過去に英単語アプリを3日で挫折。「今日やれば確実に前進している」という実感を求めている。

【あなたの役割】
- 学習者が解いた1問について、日本語でフィードバックを返す。
- 一般論や教科書的な説明は禁止。必ず「その単語・その誤答・そのビジネス場面」に即した具体的な内容にする。
- 口調はやわらかい敬体（です・ます）。1文は短く、スキマ時間でもすぐ読める分量にする。

【誤答タイプ（error_type）の選択肢】必ず次の4つのいずれかを英字キーで返すこと。
上から順に判定し、最初に当てはまったものを選ぶこと。
- "confusion": 意味が近い語と取り違えた。similar に挙がっている語の意味を選んだ場合か、正解の訳語と選んだ訳語が部分的に重なる場合（例:「提供する・与える」と「供給・提供する」）。
- "pos": 品詞がまったく重ならない語の意味を選んだ（例: 出題語が動詞で、選んだ意味は名詞のみの語）。
- "scene": 品詞は重なるが、同じビジネス場面で使う語どうしを取り違えた。
- "memory": 上記のいずれにも当てはまらず、単純にまだ記憶が定着していない。

【出力するJSONの各項目の指示】
- error_type: 不正解のときだけ上記4つから1つ選ぶ。正解のときは "memory" ではなく空文字 "" を返す。
- reason: 不正解のときだけ書く（正解のときは空文字 ""）。選んだ error_type の観点から、なぜ間違えたのかを渡された「類似語」「品詞」「ビジネス場面」を手がかりに説明する。「〇〇と混同した可能性があります。△△との違いは〜」のように1〜2文。責めず、次に活かせる形で。
- example_en: その単語を使った英文を1文。必ず渡された「ビジネス場面」で実際に使われそうな、TOEIC頻出のビジネス文脈にする。
- example_ja: example_en の自然な日本語訳。
- tip: 記憶に残す/使いこなすための一言ヒント（1文）。類似語とのニュアンスの違いや、コロケーションなど「覚えた→使える」に効く実践的な内容にする。
```

## ③ 制作メモ

### どんな体験を作ろうとしたか

TOEIC700点を目指す社会人・鈴木さんが、通勤や昼休みのスキマ時間に「今日やれば確実に前進している」と実感できる英単語アプリ **WordBoost** を作りました。既存アプリで多くの人が挫折する3つの構造的課題（①覚えた→使えない ②間違えた→理由が不明 ③続けたのに実感がない）すべてに、明確なアンサーを用意しています。1回10問・数分で完了し、通勤30分／昼休み15分に確実に収まります。

### 選んだ出題形式と、その理由（必須項目）

**出題形式：英単語 → 意味を4択（誤答の選択肢に「混同しやすい類似語」の意味を優先的に混ぜる）** を選びました。

理由は3つあります。第一に、**4択はスキマ時間で片手・数秒で解答できる**ため、鈴木さんの利用状況（通勤中・立ったまま・15分）に最も適しているからです。入力式やライティング形式は精度は測れますが、電車内では続きません。第二に、**支給データの `similar`（混同しやすい類似語）と `example_scene`（ビジネス場面）を誤答生成のスコアリングに使う**ことで、「なんとなく消去法で選べてしまう」易しい4択ではなく、意味の精密な識別を迫る良問を動的に作れるからです（類似語＝6点、訳語の部分一致＝5点、固有性の高い場面タグ一致＝3点、品詞の重なり＝1点で加点し、上位3つを誤答に採用）。これが課題①「覚えた→使えない（＝意味の区別が曖昧）」への布石になります。第三に、**入力の手間を最小化することで、学習体験の主役を「解答」ではなく「解答後のコーチング」に置ける**からです。審査で問われる「Claudeをどう体験に組み込むか」に開発リソースを集中できる形式だと判断しました。

なお、4択の弱点である「選べたが使えない」を潰すため、解答直後に**同じ単語をビジネス例文の穴埋めで再提示**し、正解した人にも「使える」かを必ず1回確認させています。

### AIをどう使うか設計した意図

**「AIが間違いを4タイプに分類し、その分類がアプリ全体を動かす」** ことを設計の中心に置きました。

Claudeには単に解説を書かせるのではなく、誤答を必ず **`confusion`（類似語の混同）/ `pos`（品詞の取り違え）/ `scene`（場面イメージ違い）/ `memory`（記憶が薄い）** の4タイプの列挙値で返させ、アプリ側の集計キーと1対1で対応させています。この構造化された分類が、(1) その場のフィードバック文の切り口、(2) ホーム画面の**弱点プロフィール**（4タイプの累積内訳バー）、(3) 次回セッションの**総括プロンプトへの入力**（「これまでの弱点1位は〇〇です」）という3か所を横断して駆動します。つまり **セッションを跨いでコーチが自分を覚えている** 状態を作りました。プロンプトでは、単語データに加えて**ユーザーが選んだ誤答の語とその品詞**、**復習フラグ**、**過去の弱点**まで必ずセットで渡し、一般論ではなく「鈴木さん本人のための言葉」になるよう徹底しています。

### 作る中で変えた判断

**判断1：スマホアプリ（Expo）→ Next.jsのWebアプリに作り直した。** 審査のしやすさ（URLで即動作確認）とAPIキーの安全管理（サーバー側の環境変数に隠す）を優先しました。

**判断2：例文とヒントを「実行時生成」から「事前生成（プリベイク）」に変えた。** 当初は毎問Claude APIで例文を生成していましたが、(a) 従量課金が発生する、(b) 解答のたびに数秒待たされスキマ学習のテンポを壊す、という2つの問題がありました。そこで**300語すべてのビジネス例文・和訳・実践ヒントをClaudeに事前一括生成させてJSONで同梱**し、実行時は即座に返す方式に変更しました。結果、**実行時のAPIコストは0円、表示は待ち時間ゼロ**になり、内容はClaudeが生成した質のまま保たれています。全300語について「例文中に対象語が含まれる」ことを自動検証済みです。

**判断3：APIキーが無くても全機能が動くようにした。** 誤答タイプ判定はローカルロジック（類似語リスト・品詞・場面の照合）でも成立するよう実装し、フィードバック文・総括文もローカルで組み立てられるようにしました。`ANTHROPIC_API_KEY` を設定すればその出力をClaude APIの応答が上書きする二層構造です。AIが落ちてもアプリは止まりません。

**判断4：誤答タイプの判定ロジックを、実データのシミュレーションで作り直した。** 当初は「支給データの `similar` に相手の語が載っているか」「場面文字列が完全一致か」で判定していました。ところが300語で分布を測ると、**誤答の82%が「記憶がまだ薄い」に落ち**、弱点プロフィールが機能していませんでした。原因は、`similar` に挙がる語の約88%が300語リストの外にあること、`example_scene` が完全一致する語がほとんどないことです。そこで判定材料を「訳語の部分一致（供給・提供する ⇔ 提供する・与える）」「品詞の集合比較（名詞/動詞 と 動詞/名詞 は同一とみなす）」「固有性の高い場面タグの一致（`財務` `人事` のように多くの語が持つ汎用タグは除外）」に組み替え、誤答選択肢の生成にも同じ指標を使うようにしました。結果、分布は **混同15% / 品詞18% / 場面20% / 記憶47%** となり、4タイプすべてが意味を持つようになりました。

### 3つの課題への具体的なアンサー

- **① 覚えた→使えない**：解答直後、その語を空欄にしたビジネス例文を提示（例：`Please accept our sincere ______ for your continued support.`）。タップで答えと和訳を開示。正解者にも必ず出します。
- **② 間違えた→理由不明**：誤答を4タイプに自動分類し、タイプ別の切り口で理由を説明。「supply と混同したようです。provide は…」のように、その語・その誤答に固有の文言になります。
- **③ 続けたのに実感なし**：700点到達度メーター（学習カバー率7割＋正解率3割）、学習済み N/300、累計正解率、連続学習日数、弱点プロフィールの内訳バーを常時表示します。

### 独自性（このアプリでないと体験できないこと）

- **弱点タイプの可視化と、それによる出題制御。** 「何問正解したか」ではなく「**どう間違えるクセがあるか**」を4タイプで蓄積・可視化し、次のセッションのAIコーチの言葉にまで反映させます。正誤率しか見ない既存アプリとの決定的な差です。
- **復習キューによる強制再会。** 間違えた語はIDで保持され、**次のセッションで「📌 復習」バッジ付きで再登場**します（最大3語を先頭に固定）。正解できて初めてキューから外れます（間隔反復ライト）。
- **プリベイク方式によるゼロコスト・ゼロレイテンシAI。** 「AIを使う＝毎回APIを叩く」という前提を外し、生成の質を保ったままコストと待ち時間を消しました。

### 使用ツール

Claude Code（設計・実装・300語コーチパックの事前生成）／ Next.js 16（App Router）／ Claude API（`claude-haiku-4-5`・構造化出力）／ Vercel（ホスティング）。学習進捗は localStorage に保存し、サーバーもDBも不要にしています（運用コスト0円）。
