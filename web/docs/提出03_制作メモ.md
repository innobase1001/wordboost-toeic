# 提出物③ 制作メモ

## どんな体験を作ろうとしたか

英検4級を目指す中学2年生・ゆうとくんが、部活のあとの15分と寝る前の10分で「今日やった分だけ合格に近づいている」と実感できる学習アプリ **WordBoost 4級** を作りました。既存アプリで多くの人が挫折する3つの構造的課題（①覚えた→使えない ②間違えた→理由が不明 ③続けたのに実感がない）すべてに、明確なアンサーを用意しています。

そのうえで、このアプリの軸は **「合格に必要なものを全部入れる」** ことです。英検4級は筆記35問・リスニング30問で、**リスニングが3分の1近く**を占めます。単語アプリだけでは、合格に必要な力の一部しかカバーできません。そこで**本番の全出題形式**をモードとして実装しました。

| 本番の出題 | 問題数 | 対応モード |
| --- | --- | --- |
| 筆記 大問1 短文の語句空所補充 | 15問 | ✏️ 空所補充 |
| 筆記 大問2 会話文の文空所補充 | 5問 | 💬 会話 |
| 筆記 大問3 日本文付き語句整序 | 5問 | 🔀 並べかえ |
| 筆記 大問4 長文の内容一致選択 | 10問 | 📄 長文（掲示・Eメール・説明文） |
| リスニング 第1部 会話の応答文選択 | 10問 | 🎧 リスニング（音声のみで応答を選ぶ） |
| リスニング 第2部 会話の内容一致選択 | 10問 | 🎧 リスニング |
| リスニング 第3部 文の内容一致選択 | 10問 | 🎧 リスニング |
| （すべての土台） | — | 📖 単語（4択・AI誤答分析つき） |
| 本番と同じ流れで通し | 18問 | 📝 実戦ミニ模試 |

## 選んだ出題形式と、その理由（必須項目）

**中心の出題形式は「英単語 → 意味を4択（誤答に『混同しやすい類似語』の意味を優先的に混ぜる）」** を選び、そこから本番の全形式へ広げました。

理由は3つあります。第一に、**4択はスキマ時間で片手・数秒で解答できる**ため、ゆうとくんの利用状況（部活後・寝る前・10〜15分）に最も適しているからです。入力式やライティング形式は精度は測れますが、疲れた夜には続きません。第二に、**単語データの `similar`（混同しやすい類似語）と `example_scene`（日常場面）を誤答生成のスコアリングに使う**ことで、「なんとなく消去法で選べてしまう」易しい4択ではなく、意味の精密な識別を迫る良問を動的に作れるからです（類似語＝6点、訳語の部分一致＝5点、固有性の高い場面タグ一致＝3点、品詞の重なり＝1点で加点し、上位3つを誤答に採用）。英検4級は `borrow / lend`、`bring / take` のように**対になる語の取りちがえ**が頻出なので、この設計がそのまま得点に効きます。第三に、**入力の手間を最小化することで、学習体験の主役を「解答」ではなく「解答後のコーチング」に置ける**からです。

なお、4択の弱点である「選べたが使えない」を潰すため、解答直後に**同じ単語を例文の穴埋めで再提示**しています。この穴埋めは**英検4級の大問1（短文の語句空所補充）とまったく同じ形式**なので、「使えるかの確認」がそのまま試験対策になります。

## AIをどう使うか設計した意図

**「AIが間違いを4タイプに分類し、その分類がアプリ全体を動かす」** ことを設計の中心に置きました。

Claudeには単に解説を書かせるのではなく、誤答を必ず **`confusion`（似た意味の語と混同）/ `pos`（品詞の取りちがえ）/ `scene`（場面のイメージちがい）/ `memory`（まだ覚えきれていない）** の4タイプの列挙値で返させ、それをアプリ側の集計キーと1対1で対応させています。この構造化された分類が、

1. その場のフィードバック文（なぜ間違えたかの説明の切り口）
2. ホーム画面の**弱点プロフィール**（4タイプの累積内訳バー）
3. 次回セッションの**総括プロンプトへの入力**（「これまでの弱点1位は〇〇です」）

という3か所を横断して駆動します。つまり **セッションを跨いでコーチが自分を覚えている** 状態を作りました。

プロンプト設計でもう一つ重視したのが、**「級のレベルを明文化して縛る」** ことです。生成AIは放っておくと大人向けの英文を書いてしまい、4級の学習者には難しすぎる例文が混ざります。そこで全プロンプトに `EIKEN4_LEVEL_RULE` として「英文は10語前後・長くても15語」「使ってよい文法は be動詞／現在・過去形／進行形／can, will, must／不定詞／動名詞／and, but, because, when／比較 まで」「英検3級以上の語は使わない」を明記し、日本語の説明も中学生に伝わる言葉づかいに縛りました。出力は構造化出力（zod）でJSONに固定しています。

## 発音・リスニングをどう実現したか

リスニングが3分の1を占める以上、**音がないアプリは4級対策として不完全**です。かといって録音されたネイティブ音源は、音源のライセンス費用が発生し「実行時コスト0円」という設計方針と両立しません。

そこで**ブラウザ標準の Web Speech API**（`lib/speech.js`）を使い、端末に入っている音声から**ネイティブ品質の en-US 音声**（Google US English / Microsoft の Natural 音声 / Apple の Samantha など）を名前で優先選択する実装にしました。追加のAPIキーも通信も不要で、費用は0円、オフラインでも鳴ります。🐢ボタンで0.65倍速の再生もできます（聞き取れなかったときの2回目用）。

リスニングモードでは**本文を一切表示しません**。第1部にいたっては**選択肢も音声のみ**で、聞き取れなければ答えられない、本番と同じ条件にしています。

## 作る中で変えた判断

**判断1：スマホアプリ（Expo）→ Next.js のWebアプリに作り直した。** 審査のしやすさ（URLで即動作確認）とAPIキーの安全管理（サーバー側の環境変数に隠す）を優先しました。

**判断2：例文とヒントを「実行時生成」から「事前生成（プリベイク）」に変えた。** 当初は毎問Claude APIで例文を生成していましたが、(a) 従量課金が発生する、(b) 解答のたびに数秒待たされスキマ学習のテンポを壊す、という2つの問題がありました。そこで**300語すべての例文・和訳・実践ヒントをClaudeに事前一括生成させてJSONで同梱**し、実行時は即座に返す方式に変更しました。会話・語句整序・長文・リスニングも同様に**解説つきで事前生成**しています。結果、**実行時のAPIコストは0円、表示は待ち時間ゼロ**になり、内容はClaudeが生成した質のまま保たれています。

**判断3：APIキーが無くても全機能が動くようにした。** 誤答タイプ判定はローカルロジック（類似語リスト・品詞・場面の照合）でも成立するよう実装し、フィードバック文・総括文もローカルで組み立てられるようにしました。`ANTHROPIC_API_KEY` を設定すればその出力をClaude APIの応答が上書きする二層構造です。AIが落ちてもアプリは止まりません。

**判断4：誤答タイプの判定ロジックを、実データのシミュレーションで作り直した。** 当初は「`similar` に相手の語が載っているか」「場面文字列が完全一致か」で判定していましたが、300語で分布を測ると誤答の大半が「まだ覚えきれていない」に落ち、弱点プロフィールが機能しませんでした。原因は、`similar` に挙がる語の多くが300語リストの外にあること、`example_scene` が完全一致する語がほとんどないことです。そこで判定材料を「訳語の部分一致（借りる ⇔ 貸す）」「品詞の集合比較（名詞/動詞 と 動詞/名詞 は同一とみなす）」「固有性の高い場面タグの一致」に組み替えました。場面タグは `学校・図書室` のように **〈大分類・小分類〉** で持たせ、`学校`（44回）`おでかけ`（40回）のように多くの語が共有する大分類19個は「同じ場面で混同した」根拠として弱いので除外し、固有な小分類125個だけを使っています。

**判断5：語形変化の照合を、前方一致から「取りうる形を作って完全一致」に作り直した。** 穴埋めを作るには例文から出題語を見つける必要がありますが、旧実装（語幹の前方一致）は `cry → cried` や `save → saving` を拾えず、逆に `play` が `player` を隠してしまう危険がありました。英検4級は**不規則動詞の過去形が出題範囲**なので、例文でも `bought / went / wrote` を積極的に使いたい。そこで `lib/inflect.js` に、不規則動詞58語・不規則複数形8語の表と、規則変化（三単現・複数形・-ed・-ing・比較級）の機械生成を実装し、**その語が取りうる形をすべて作ってから語として完全一致で探す**方式に変えました。`stop → stopped` のように語尾を重ねるかはつづりだけでは決まらない（`visit → visited` は重ねない）ため、両方を候補に入れて実際に当たった方を採用します。これで**全300語で穴埋めが作れる**ことを自動検証しています。

## 3つの課題への具体的なアンサー

| 業界課題 | このアプリの実装 |
| --- | --- |
| ① 覚えた→使えない | 解答直後、その語を**空欄にした例文**を提示（`I ______ my bike to the park.`）。これは大問1と同じ形式なので、そのまま試験対策になる。タップで答えと和訳を開示し、正解者にも必ず出す。🔊で発音も確認できる |
| ② 間違えた→理由不明 | 誤答を**4タイプに自動分類**し、タイプ別の切り口で理由を説明。「lend と混同したようです。borrow は「借りる」で…」のように、その語・その誤答に固有の文言。語彙以外のモードも1問ずつ解説つき |
| ③ 続けたのに実感なし | **4級合格到達度メーター**（語彙カバー率4割＋筆記の正解率3.5割＋リスニングの正解率2.5割）、覚えた単語 N/300、**技能別の仕上がりバー**、連続学習日数、**弱点プロフィールの内訳バー**を常時表示 |

到達度の重みは、本番の配点（筆記35問・リスニング30問）に「語彙はすべての土台」という点を加味して決めました。まだ解いていない区分は0として扱うので、**練習した分だけ数字が伸びます**。

## 独自性（このアプリでないと体験できないこと）

- **4級の全出題形式が1つのアプリに揃っている。** 単語帳アプリでも過去問アプリでもなく、大問1〜4とリスニング第1〜3部を、それぞれ本番と同じ条件（リスニングは本文非表示、第1部は選択肢も音声のみ）で練習できます。実戦ミニ模試で通しの実力も測れます。
- **弱点タイプの可視化と、それによる出題制御。** 「何問正解したか」ではなく「**どう間違えるクセがあるか**」を4タイプで蓄積・可視化し、次のセッションのAIコーチの言葉にまで反映させます。
- **復習キューによる強制再会。** 間違えた語はIDで保持され、**次のセッションで「📌 復習」バッジ付きで再登場**します（最大3語を先頭に固定）。正解できて初めてキューから外れます（間隔反復ライト）。
- **プリベイク＋ブラウザ音声によるゼロコスト設計。** 「AIを使う＝毎回APIを叩く」「音声＝音源を買う」という前提を両方外し、質を保ったままコストと待ち時間を消しました。

## 使用ツール・構成

Claude Code（設計・実装・300語コーチパック／筆記・リスニング問題データの事前生成）／ Next.js 16（App Router）／ Claude API（`claude-haiku-4-5`・構造化出力）／ Web Speech API（発音・リスニング）／ Vercel（ホスティング）。学習進捗は localStorage に保存し、サーバーもDBも不要にしています（運用コスト0円）。
